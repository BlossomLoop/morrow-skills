# 技术路线参考（通用示例）

原文件名为兼容已有引用保留。原始内部选型表、文档地址、专有 SDK、组织推荐等级和批准版本范围已移除。本文件只描述仓库包含的模板及选型时需要确认的信息，不代表任何组织的技术规范。

## 仓库包含的模板

| 组件类型 | 模板 | 使用前需要确认 |
| --- | --- | --- |
| Java 服务 | Java + Spring Boot | 现有 Java 版本、框架兼容性、数据库访问方式 |
| Python 服务 | Python + FastAPI | 团队经验、异步边界、依赖和部署方式 |
| Web 管理台 | Vue 3 + TypeScript + Vite | 现有前端栈、页面范围、浏览器约束 |
| Go 服务 | Go + Gin | 并发模型、依赖、可观测性要求 |
| Android 客户端 | Kotlin | 目标系统版本、设备能力和权限范围 |
| 跨平台客户端 | Flutter | 目标平台、插件依赖和原生集成边界 |
| 其他技术栈 | common 通用目录 | 明确专用模板缺失，不替用户更换已选技术栈 |

## 选型顺序

1. 用户明确的要求和项目硬约束。
2. Brownfield 项目的现有实现、团队能力及迁移成本。
3. 组件职责、非功能要求、部署限制和维护成本。
4. 比较候选方案，记录理由、风险与待验证项，再由用户确认。

用户没有提供组织规范时，应登记为待确认信息，不自行编造白名单、批准版本或强制推荐等级。

## 数据和集成

数据库、缓存、消息服务和外部 API 按具体需求单独比较。已有项目优先说明保留现有组件的方案；新增依赖需记录需求依据、故障处理和替换成本。

版本、许可证和漏洞状态需要在实际选型时核对公开资料或用户提供的依据。本文件不维护未经核验的版本范围。
