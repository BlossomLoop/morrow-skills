# morrow-architecture-design 评分卡

## 评分说明

每个维度按 1-10 分打分，总分按加权平均计算。

本评分卡优先评估"关键架构问题是否被想透 + 是否形成可追溯的治理结构"，而不是"文档是否写满"。

## 评分维度

| 维度 | 权重 | 评分 | 说明 |
|------|------|------|------|
| 问题定义与约束建模 | 12% |  | 是否明确目标、角色、场景、硬约束、假设；**是否完成 US/FR/SC 编号** |
| 项目宪法质量 | 6% |  | NON-NEGOTIABLE 原则 ≥ 3 条；可观测手段清晰；能直接拒 PR |
| 架构驱动因素提炼 | 8% |  | 是否识别功能、非功能、集成与风险驱动项，非功能是否量化 |
| 候选方案比较质量 | 15% |  | ≥ 2 套方案；对比维度 ≥ 7；推荐 + 不推荐 + 何时重评三件套 |
| 反工程化审视 | 7% |  | §8 三个追问全部作答；Parking Lot ≥ 3 条；§8.5 复审已回写 |
| 组件与边界设计 | 12% |  | 组件职责 / 不负责 / 依赖方向 / 数据归属 / 信任边界 |
| 核心链路与数据设计 | 12% |  | 核心链路 ≥ 3；DDL 级 schema；状态机；契约含 Schema + 校验链 + 反例 |
| 风险与演进独立性 | 8% |  | `risk-and-evolution.md` 独立存在；V / W / E 编号齐；演进触发量化 |
| ADR 质量 | 10% |  | 基线 4 份 + 动态追加合理；FR 回链 + 宪法条款引用；6 段完整 |
| 编号闭环与宪法遵守 | 6% |  | US ↔ FR ↔ SC ↔ API ↔ ADR 链路可追溯；无违反 NON-NEGOTIABLE |
| 产物完整性 | 2% |  | 覆盖关键文档、图示、契约与必要骨架 |
| 完成门禁 | 2% |  | Phase 12 自查 + Constitution Re-check 实际执行 |

合计 100%。

## 深度检查清单

- 是否明确回答了"为什么做这个系统，而不是别的方案"
- **给定 FR-003，能否在 API 设计里找到至少一条服务它的接口？**
- **给定 ADR-005，能否在 `requirement-analysis.md` 找到它背后要满足的 FR / SC？**
- 是否给出了至少 3 条核心业务链路
- 是否解释了为什么推荐该方案，而不是另一个候选方案
- 是否明确了哪些地方先简单做，哪些条件下再升级
- 是否识别了最脆弱的 3 个点
- 是否说明了关键数据的归属、一致性和状态流转
- **6 个月后有人问"该不该升级到 B 方案了"，`risk-and-evolution.md §7` 能直接给出答案吗？**
- **宪法 §1 的每条原则，能否直接拒掉一个违反它的 PR？**
