# 历史架构评测问题归纳

> 这是历史问题的脱敏归纳，不是可复现的原始评测报告。项目、客户、供应商、设备细节、具体时间预算、评分和内部产物路径已移除；以下条目只保留可复用的问题与验证方法，不能用作当前版本通过的依据。

| 问题 | 检查方法 |
| --- | --- |
| 任务与边界 | 先检查项目现状和输入完整性，再进入方案设计。不要把外部系统可用性写成已确认事实。 |
| 架构产物 | 需求编号应能关联方案、ADR 和 API；文件存在不等于内容覆盖需求。 |
| 骨架约束 | 架构阶段仅生成启动入口和基础配置，不能提前创建带业务语义的 Controller、Service 或 Provider 空壳。 |
| 验收状态 | 未完成的外部契约、PoC 和确认项必须保留开放状态，不能因文档齐全宣布 Final。 |
