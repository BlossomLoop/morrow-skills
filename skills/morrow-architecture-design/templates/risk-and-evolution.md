## 1.5 语境专属风险族（按项目类型勾选）

> 通用风险维度（功能 / 非功能 / 集成）容易把"语境特有的风险"糊进通用条目，导致无法制定专门的监控阈值和预案。
> 如果你的项目落在下面任一语境，上面的 §1 脆弱点清单必须**各自独立**登记 V-xxx，不得合并到通用条目。

- [ ] **展会 / Demo 场景**（勾选后以下 4 项必须各自独立 V 条目）：
  - [ ] V-离线降级：外网 / 内网全断时必须能播放预录脚本或本地 demo 数据
  - [ ] V-限流兜底：第三方 LLM / API QPS 限制被触发时的 fallback 路径
  - [ ] V-硬件异构：现场机型 / 浏览器 / 操作系统不一致下的最低可用基线
  - [ ] V-现场网络：场馆带宽被邻展位占满 / 防火墙拦截 WebSocket / TLS
- [ ] **生产 SaaS 场景**：
  - [ ] V-多租户隔离越权
  - [ ] V-合规触发（GDPR / 等保 / 数据跨境）
  - [ ] V-SLA 违约（按客户合同分级）
- [ ] **内部工具 / 运维平台场景**：
  - [ ] V-误操作影响范围（批量下发 / 脚本注入）
  - [ ] V-凭证权限泄漏
- [ ] **移动端 / IoT / 嵌入式场景**：
  - [ ] V-离线同步冲突
  - [ ] V-固件升级失败回滚
  - [ ] V-电量 / 存储 / 网络切换

**判定法则**：如果读完上面某一族觉得"我们项目当然要考虑这些"但在 §1 里找不到对应的 V 编号，那就是漏了。
