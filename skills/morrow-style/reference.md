## 一、黑名单全集

### 1、绝对禁用（纯官腔/AI 指纹词，任何语境都不用）

赋能、多维、全域、纵深、提质、增效、抓手、基石、内核、底色、范式、图景、新赛道、破局、突围、深耕、聚力、焕新、赋能升级、价值重塑、底层逻辑、核心抓手、顶层设计、生态布局、差异化优势、可持续路径、价值增量、多维协同、资源整合、绘就宏伟蓝图

### 2、条件禁用（指具体动作/对象时可用，作空洞修饰时禁用）

- **落地**：可以说"项目在联通渠道落地"（具体交付），不可以说"推动方案高质量落地"（口号）
- **迭代**：可以说"2.4 迭代的 bug review"（具体版本），不可以说"持续迭代优化"（空话）
- **闭环**：可以说"这个流程没有形成闭环，缺少 X 环节"（指具体流程缺口），不可以说"打通全链路闭环"
- **高效/精准**：后面必须跟具体指标或机制，否则删

### 3、AI 标志性套话短句（出现即删改）

站在 XX 的视角下、从 XX 维度进行剖析、为 XX 注入全新动能、构建 XX 一体化体系、打通 XX 全链路闭环、实现 XX 高质量发展、兼具 XX 与 XX 双重价值、由此可见、不难看出、总而言之、综上所述、在当下数字化浪潮之下、解锁 XX 全新可能性、赋予 XX 全新内涵、二者相辅相成、相得益彰、既要…也要…同时兼顾、以 XX 为依托以 XX 为导向

### 4、空洞书面语

不可否认、毋庸置疑、长远来看、从长远视角、值得注意的是（个人习惯用"需要注意的是"）、场景落地（作口号时）

### 5、AI 高频词（吸收自 humanizer-zh）

此外、深入探讨、不容忽视、彰显、凸显、标志着、见证了、不断演变的格局、关键转折点、不可磨灭、深深植根于、织锦、是…的证明、宝贵的、充满活力的、令人叹为观止、坐落于、迷人的、开创性的（比喻义）、深刻的（泛用）、无缝、直观且强大、蓬勃发展、焕发生机

### 6、协作痕迹（对话残留，出现即删）

希望这对您有帮助、请告诉我、当然！、一定！、您说得完全正确、需要我…吗、以下是、值得一提的是

### 7、直译腔技术词（英文术语直译，中文工程口语不这么说；本义语境可用，直译义返工。随写作积累，用户否掉一个添一个）

- **证据**（evidence 直译）：代码评审、工程语境说"测试结果""验证结果""依据"；法律、安全取证等本义语境可用（2026-07 七周年演讲 P4 用户否掉）
- **洞察**（insight 直译）：说"发现""结论""判断"
- **旅程**（journey 直译）：如"用户旅程""成长旅程"，说"过程""路径""流程"；本义出行可用
- **拥抱**（embrace 直译）：如"拥抱变化""拥抱 AI"，说"接受""开始用""跟进"；本义动作可用
- **控制面**（control plane 直译）：说"管控层"；英文官方产品名（如 GitHub agent control plane）原文保留（2026-07 七周年演讲全片用户否掉）

### 8、伪对立式抬高（出现即拆句）

这类句子先虚设一个次要对象，再用转折抬高真正观点。常见形式：

- 问题不在于 A，而在于 B
- 关键、重点、核心不在于 A，而在于 B
- 真正需要关注的不是 A，而是 B
- 与其说 A，不如说 B
- 不仅仅是 A，而是 B

改写时直接陈述 B。A 确实需要保留时，另起一句说明两者的实际关系，不制造对立。

改写前：

> 问题不在于某次编译结果是假的，而在于不同检查回答的是不同问题。

改写后：

> 不同检查回答的是不同问题。编译通过只覆盖工程检查。

改写前：

> 我们的目标不是限制 Agent，而是保证结果可以追踪。

改写后：

> 我们的目标是保证结果可以追踪。Agent 的执行范围由任务合同限制。

## 二、文体模板

### 1、技术分享/经验文

```markdown
**摘要：** 一段话说清背景 + 本文讲什么，可含限定说明（如"需要注意的是，部分内容可能不适用后续版本"）
**关键词：** 2-4 个

# 1 主题一
正文。开头惯例：「目前针对 XX 的文章已经很多了，本文不再介绍 XX，本文的重点是…」式直接定位。

| 对比项 | 方案A | 方案B |（参数/版本/方案对比用表格，可用居中对齐）

> tips：坑和注意事项放引用块，多条时用 1、2、3、编号

## 1.1 子主题
代码块给真实可跑的代码，带 output：
```java
// 代码
-----------output------------
// 输出
```

# 2 注意事项（结尾以实质章节收束，无总结段）
```

要点：

- 标题格式 `# 1` 或 `# 1、` 均可，二级 `## 1.1`
- 正文两级编号：`1、` 套 `1）`
- 链接直接内联：`[开放平台](url)`
- 全文无"综上所述"式收尾，最后一章通常是"注意事项"或具体建议

### 2、周报/工作摘要

```markdown
# YYYYMMDD
1、类别 - 事项名词短语
- 子项（动作名词化：沟通、梳理、评审、排查、跟进、编写、调研）
2、类别：
- 子项
> 备注/待办直接放引用块
```

要点：

- 类别前缀如：材料、产研、会议、调研、支撑、coding、问题排查、绩效
- 同一项目/领域下有多个动作时，用项目名作类别、动作作子项（如 `1、虾盒：` 下挂 `- 面试：前端复试 2 个`），不要用动作当类别
- 不写完整句、不加句号、不写心得感想
- 链接原样贴，可用 ==高亮== 标记待办、@人名 标记相关人

### 3、汇报/规划/发言材料（口语）

专治 AI 演讲腔，要点：

- 短句为主，第一人称正常用，只陈述亲历的事实和判断
- 讲具体的事：项目名、人数、周期、数字（如"2 前 2 后缩成 1 前 1 后，周期从 3 周到 1 周"）
- 观点 = 结论 + 理由，直接给，不做悬念设计
- 金句数 = 0：每页/每段收尾是普通陈述句，不设计"可引用的话"
- 比喻数 = 0：说机制本身（说"Sandbox 限制文件和网络访问"，不说"门禁"）
- 段落结构允许不齐整：有的长有的短，禁止每段同构（引入→展开→金句收尾是 AI 指纹）
- 结尾：说完最后一件事就停，致谢/祝贺一句话即可

## 三、改写对照示例

### 示例 1：官腔汇报去味

改写前：

> 在当下数字化浪潮之下，大模型技术正在为产品体验注入全新动能。我们通过构建大模型接入一体化体系，打通了从需求到落地的全链路闭环——不仅提升了人机交互的智能化水平，更为产品竞争力的价值重塑奠定了坚实基石。展望未来，我们将持续深耕大模型应用场景。

改写后：

> 目前公司内外大量产品在接入大模型，通过大模型丰富产品的人机交互方式，优化产品效果。我们统一了大模型接入流程，需求提出到上线走同一条链路。后续计划把大模型接入扩展到 X 和 Y 两个产品线。

改动说明：删时代铺垫、删"注入动能/一体化体系/全链路闭环/价值重塑/基石/深耕"、删破折号和"不仅…更…"、"展望未来"换成具体计划。

### 示例 2：演讲稿平实化

改写前（AI 演讲腔，注意：让模型"改得像真人"通常会加重表演腔，必须按本规则硬约束）：

> 再说 Harness。这个词不太好翻，我把它理解成 Agent 的工位加门禁。Worktree 和容器让几个任务别踩同一份代码，Sandbox 管住文件和网络，Hooks 负责那些不能靠"请你务必遵守"的规则，Steering 用来中途拉一把，日志则是出问题以后还能回放。我现在选工具，除了看模型强不强，真的会多问一句：它有刹车吗？

改写后：

> 再说 Harness。它解决的是 Agent 执行过程的隔离和控制问题。Worktree 和容器做任务隔离，避免多个任务改同一份代码；Sandbox 限制文件和网络访问；有些规则写在提示词里模型不一定遵守，需要用 Hooks 强制拦截；Steering 用于中途人工干预；日志用于出问题后回溯。我现在选工具，除了看模型能力，还会看这套控制机制全不全。

改动说明：删"工位加门禁"和"刹车"比喻，直接说机制；删金句式收尾反问，换成平实陈述；五个组件的说明保留，信息一点没少。

### 示例 3：技术分享开头

改写前（AI 默认输出：格式不对、用词油滑、三段式枚举、俗套祝愿收尾）：

> 最近团队里越来越多的服务开始接入 MCP，把内部工具、数据源封装成 MCP server 供各类 AI 客户端调用。上线过程中我们发现，MCP server 直接裸跑并不省心……这些坑官方文档着墨不多，我们踩了一轮才摸清门道。本文把这段时间积累的 nginx 代理配置经验做个整理……希望能帮后面接入的同学少走些弯路。

改写后（个人风格）：

> **关键词：** MCP nginx 反向代理
>
> # 1、概述
> 目前针对 MCP 的科普文章已经很多了，本文不再对 MCP 进行介绍，重点说明 nginx 代理配置中的问题及解决方式，主要包含两点：
> 1、SSE 长连接的缓冲及超时配置；
> 2、base_uri 和 endpoint 需要同时代理的问题；

改动说明：补上摘要/关键词头部和数字标题结构；"裸跑/掐断/摸清门道/少走弯路"这类油滑表达全删；枚举收敛为两点并编号；删祝愿式收尾。

## 四、量化基线（正向，从本人亲笔文章算出 · 2026-08-22）

> 黑名单管"不该写什么"，量化基线管"本来长什么样"。两条合起来，双向可测。
> 基线来源：本人三篇技术分享亲笔文章（星火集成 / 大模型产品化 / MCP 交互流程分析）。
> 机器检查：`scripts/check_baseline.py 待检文件`，命中容差外即返工。

| 指标 | 本人基线 | 容差 | 含义 |
|------|---------|------|------|
| 平均句长 | 43 字 | 30-55 | 长句主导，不是短句风 |
| 长句占比（≥50字） | 38% | 15-55 | 一个长句把背景/版本/能力一次说完 |
| 短句占比（≤15字） | 25% | 10-40 | 长短交错，短句做顿点 |
| 句长 CV（节奏起伏） | 0.76 | 0.5-1.0 | 节奏有起伏，不平铺 |
| 加粗频率 | 1.7 次/千字 | ≥0.5 | 关键信息加粗 |
| 习惯词密度 | 14.7 次/千字 | ≥5 | 目前/如/建议/注意/需要… |
| 引用块（tips/注意） | 18.7 块/篇 | ≥2 | 坑和提醒放引用块 |

**写作提示（基线翻译成可照做的指令）**：
- 每 3-4 个句子里，安排 1 个 ≥50 字的"压阵长句"，把背景、版本、能力一次说完（如「截止目前，星火最新版本为3.5…七个方面进行了全面升级，并提供了system角色预设及functioncall等API能力」）。
- 长句之后接一个短句做顿点（「各产品的交互流程会有区别」「表格中金额进行了脱敏」）。
- 全文节奏要像心电图，不要像匀速直线：CV 低于 0.5 = 一水的短句，这是 AI 指纹。
