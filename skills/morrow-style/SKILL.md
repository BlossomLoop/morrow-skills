# morrow-style：去 AI 味 + 个人风格写作

## 核心原则

平实直接，信息密度高，说完就停。把话说清楚比说漂亮重要，宁可平淡，不可油滑。

**违反规则的字面就是违反规则的精神。** 不存在"这一处金句效果很好所以保留"的例外。

## 两种模式

- **生成模式**：写新内容时，按通用底座 + 对应文体模板直接产出
- **改写模式**（默认除味保结构）：只删 AI 痕迹、换词、调句，不动章节结构和内容组织；仅当用户显式要求重排时，才按文体模板重组

## 工作流程

0. **先完整读取同目录下的 [reference.md](reference.md)**（黑名单全表 + 文体模板 + 改写对照示例都在里面，不读完不动笔）
1. 判断文体：周报条目 / 技术分享 / 汇报发言 / 其他（其他只用通用底座）
2. 按「通用底座」写作或改写
3. 套用对应文体格式（模板见 [reference.md](reference.md)）
4. 交付前过一遍自检清单

## 通用底座（怎么写）

- 开头直接进入主题。背景一两句说完，不做时代背景铺垫
- 陈述事实用平直句式：「目前 X 是 Y」「X 需要 Y」「建议 X」
- 举例用「如」「比如」引出，例子必须具体：版本号、参数名、数字、文件名、项目名
- 坑和提醒单独放 `> tips：` 或 `> 注意` 引用块
- 层级用数字编号：一级 `1、`，二级 `1）`；关键信息可加粗（个人习惯，放心用）
- 参数、版本、方案对比用表格
- 句式短句为主，允许多逗号长句连缀，不追求句句精致
- 结尾说完即止：以最后一条实质内容或实用提醒收束，不写总结段、不展望、不升华

常用词（符合个人习惯）：目前、截止目前、需要注意的是、建议、如、比如、相对、基于、沟通、梳理、评审、排查、跟进、调研

## 硬禁项（出现即返工）

1. **黑名单词汇与套话**（全表见 reference.md）：赋能、闭环、抓手、深耕、破局、底层逻辑、总而言之、由此可见、在当下 XX 浪潮之下……
2. **比喻和拟人**：不打比方，直接说机制本身。反例：把 Sandbox 说成"门禁"，把日志说成"记录仪"，把控制机制说成"刹车"
3. **金句**：任何设计过的、可引用的收尾句都删掉，换成平实陈述。发言稿全篇金句数也是 0
4. **三段式排比**：「X 了，Y 了，还 Z 了」「既要 X 也要 Y 更要 Z」，改成两项或拆开说
5. **设问自答**：「问题出在哪？」「为什么这么说？」——直接给答案
6. **欲扬先抑转折模板**：「听起来 X，但我会问 Y」「第一反应 X，第二反应 Y」
7. **伪对立式抬高**：「不是 X，而是 Y」「问题不在于 X，而在于 Y」「关键不在于 X，而在于 Y」「与其说 X，不如说 Y」「这不仅仅是 X」。这类句式通常先虚设一个次要对象，再抬高真正观点。直接陈述 Y，需要交代 X 时另起一句写事实关系
8. **破折号（——）、emoji**。中文引号（""「」）是标准用法，正常使用，不算 AI 痕迹
9. **宏大意义拔高**：标志着、彰显、见证了、里程碑、新篇章
10. **模糊归因**：专家认为、业内普遍、观察者指出——要么给具体出处，要么删
11. **「-ing 式」肤浅分析尾巴**：句尾挂「体现了…」「为…奠定了基础」「推动着…」

## 交付前自检

先跑机械扫描（输出已落盘时对文件跑，未落盘时把文本写入临时文件再跑）。扫描器会跳过 Markdown 围栏代码块，避免把代码示例当成正文：

```bash
# 第一条：绝对禁用词、套话、破折号和伪对立句式。命中数必须为 0
python3 "<morrow-style/SKILL.md 所在目录>/scripts/scan_style.py" 待检文件

# 第二条：条件禁用词 + 直译腔技术词，命中处逐一人工判断（指具体动作/对象或本义可用，作空洞修饰或英文直译义返工）
grep -nE '落地|迭代|闭环|高效|精准|证据|洞察|旅程|拥抱' 待检文件

# 第三条（正向）：量化基线，节奏是否符合本人风格（长句主导、长短交错）。命中容差外即返工
python3 "<morrow-style/SKILL.md 所在目录>/scripts/check_baseline.py" 待检文件
```

再过人工清单：

- [ ] 第一条扫描命中数 = 0，第二条 grep 命中处逐一判断过，第三条基线检查全 OK
- [ ] 比喻数 = 0，金句数 = 0
- [ ] 无三段式排比、无设问自答、无欲扬先抑转折
- [ ] 结尾没有总结/展望/祝愿段
- [ ] 例子有具体数字/参数/名称，不空泛
- [ ] 格式符合 reference.md 对应文体模板
- [ ] 若发现黑名单没拦住、但确实是 AI 味的新表达（机械扫描漏网），记下来，可调用 `morrow-style-tuner` 把它固化进规则

## 常见借口（都不成立）

| 借口 | 现实 |
|------|------|
| "这个金句是全文点睛之笔" | 用户的原话：受不了金句轰炸。删。 |
| "比喻能帮听众理解" | 用户的真实文章比喻数为零。说机制本身。 |
| "演讲稿需要感染力" | 用户要的感染力来自具体的事和数字，不来自修辞。 |
| "改写后太平淡了" | 平淡就是目标。信息密度高的平淡不是缺点。 |
| "三个例子更全面" | 两项优于三项。三段式是 AI 指纹。 |

## 与 humanizer-zh 的关系

本 skill 自包含，已吸收 humanizer-zh 的通用规则并按个人习惯裁剪：

- **保留个人习惯**（humanizer-zh 反对但这里以个人为准）：加粗强调、「1、xxx：」数字编号列表、结构化分层
- **不采纳**：注入幽默感、文学化的情绪表达（"凌晨三点让人不安"式写法）。个人风格是平实克制，不是"有灵魂的散文"
- 第一人称在发言稿里正常用（"我""我们"），但只用于陈述亲历的事实和判断，不用于制造情绪
