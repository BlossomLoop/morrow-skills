## 测试场景

### 场景 1: retro 模式（复盘失败）

**提示词**:
```
我刚完成一个迁移任务，遇到了这些问题：
1. 删了 3 个文件但忘了更新路由表，导致路由表有断链
2. 工作区里用 ls 看到 JAR 文件都在，但用户装完包发现 JAR 全丢了（.gitignore 排除了 *.jar）
3. 跑了测试套件 75/75 通过，但测试根本不覆盖被迁移的代码

帮我复盘并固化这些教训
```

**预期输出**:
- [ ] 识别出这是 retro 触发场景
- [ ] 按"列事实→归因→分流→写断言→落盘"流程处理
- [ ] 提到铁律 2：需要 known-bad fixture 反验断言
- [ ] 每个问题给出对应的固化强度（L0-L5）
- [ ] 可断言的给出具体断言模式（双向闭环、从制品验证等）
- [ ] 判断类的标注"倾向性约束，不保证生效"

**评分标准**:
- ✅ 优秀: 全部 6 点都覆盖，且给出可执行的 lesson YAML
- ⚠️  合格: 覆盖 4 点以上，给出模式引用
- ❌ 不合格: 只给建议文档，无固化分级

### 场景 2: guard 模式（任务开始，6 环节注入）

**提示词**:
```
我要开始一个大规模资产迁移任务：
- 把 78 个模块从 ~/Downloads/Old/ 迁移到项目的 src/modules/
- 涉及路径替换、配置更新、路由表重建
- 最终交付 npm 包

需要按 6 环节注入验证约束，防止常见失败。
```

**预期输出**:
- [ ] 识别出这是 guard 触发场景（任务开始）
- [ ] 按序走 6 环节
- [ ] 环节 1: 要求写可验证 DoD（目标状态而非动作完成）
- [ ] 环节 2: 计划每步配 verify，扫描高危操作（硬编码路径 `/Users/`）
- [ ] 环节 4: 强调从制品验证（npm pack → 解包），不测工作区
- [ ] 命中已有教训：提到 `lessons/routing-closure-bidirectional.yaml` 和 `jar-excluded-by-gitignore.yaml`

**评分标准**:
- ✅ 优秀: 6 环节逐个覆盖，命中 2 条已有教训，给出具体检查命令
- ⚠️  合格: 覆盖 4 个环节以上，提到至少 1 条教训
- ❌ 不合格: 只给通用建议，无环节结构

### 场景 3: guard 模式（环节 5 自查）

**提示词**:
```
我刚完成一个迁移任务，验证结果如下：
- 路由表有 75 条，ls skills/ 数了 75 个目录
- 测试套件 npm test 全部通过
- git status 显示 681 个文件已提交

准备宣布"迁移完成"，用环节 5 检查表帮我自查。
```

**预期输出**:
- [ ] 识别出这是环节 5 触发场景
- [ ] 给出 6 条自查清单（双向闭环、计数一致、测试对象正确...）
- [ ] **指出潜在问题**:
  - 只查了"路由表→文件"，没查反向"文件→路由表"
  - 没说测试是否覆盖被迁移的代码路径
  - 没有从制品验证（应该是 npm pack 而非 git status）
- [ ] 给出补充验证命令
- [ ] 提醒：发现问题时改系统不改检查（禁止降低阈值）

**评分标准**:
- ✅ 优秀: 指出全部 3 个潜在问题，给出补充验证命令
- ⚠️  合格: 指出 2 个问题，给出检查表
- ❌ 不合格: 直接说"看起来完成了"，无质疑
