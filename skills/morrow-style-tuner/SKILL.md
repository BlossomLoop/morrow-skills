# morrow-style-tuner：morrow-style 规则调优器

## 职责与关系定位

本 skill 是 morrow-style 的元层：morrow-style 负责按规则写/改文档，本 skill 负责改进那套规则。

被改进对象固定为两个文件：
- `~/.claude/skills/morrow-style/SKILL.md`（工作流 + 硬禁项 + 自检机械扫描）
- `~/.claude/skills/morrow-style/reference.md`（黑名单 7 类全表 + 文体模板 + 改写对照）

本 skill 不带自己的 reference.md，它的数据就是上面两个文件。开工前先用 Read 读这两个文件的当前内容，一切分类、查重、联动都基于读到的实际内容，不靠记忆。

两条触发路径跑同一条五步流水线，不分模式：
1、人工投喂：审核文档时发现 AI 味词句，调用本 skill 并把词句给它。
2、自改进回写：morrow-style 自检发现机械扫描漏网、但确实 AI 味的新表达时，提示调用本 skill。

## 五步流水线总览

对输入里的每个候选词/句，依次跑：归一化输入 → 准入测试 → 分类+反思 → 生成 diff → 确认后落地。下面各节逐步展开。

## 第 1 步 归一化输入

把输入拆成独立候选。输入可能是单词（如「赋能」）、短语（如「打通全链路闭环」）、句式（如「不是 X 而是 Y」）、或整句带吐槽。

- 对整句：先抽出到底是哪个词或哪个结构有 AI 味，只把那部分当候选，不把整句原样当条目。
- 对每个候选标疑似类型：词 / 短语 / 句式。
- 输出一张候选清单，逐条列出。

## 第 2 步 准入测试

每个候选过三问，任一不过就丢弃并写明理由，不硬凑：

1、是不是真 AI 指纹？判断它是普遍的 AI 腔套话，还是只是这一处用得不好、或属于用户个人风格。morrow-style 明确保留的个人习惯（加粗强调、「1、xxx：」数字编号、结构化分层）不算 AI 味，一律挡掉。
2、是否已被现有规则覆盖？拿候选去比对刚读到的 reference.md 黑名单 7 类全表、以及 SKILL.md 两条 grep。已覆盖的不重复加，转错误处理里的「冲突和重复」。
3、能否给出替代写法？说不出该怎么改的，说明还没想清楚，不录入。

## 第 3 步 分类 + 反思

对过关的候选：

1、归类：归到黑名单 7 类里的哪一类（1 绝对禁用 / 2 条件禁用 / 3 套话短句 / 4 空洞书面语 / 5 AI 高频词 / 6 协作痕迹 / 7 直译腔技术词）。若它是比喻、金句、三段式排比、设问自答、欲扬先抑、否定式排比等结构性问题，归到 SKILL.md 的「硬禁项」编号清单，而不是 7 类词表。
2、反思旧规则为何没拦住：是黑名单漏词、还是机械扫描 grep 正则没覆盖这个词、还是缺一条硬禁项。把结论写出来。
3、定配套动作：要不要配一条改写对照示例（放 reference.md 三、改写对照，或对应类目下）；要不要带日期加语境归因（仿照第 7 类「（2026-07 七周年演讲用户否掉）」写法）；按「数据一致性联动规则」的 grep 联动规则，判断这个类别要不要同步动哪条 grep。

输出每个候选的归类结果：类别号、旧规则漏因、是否配改写示例、要动哪条 grep（第一条 / 第二条 / 不动）。

## 第 4 步 生成 diff

按第 3 步结果，产出对 reference.md 和/或 SKILL.md 的精确改动，以 diff 形式呈现，每处改动写明理由。

明确标注两类改动：
- 黑名单加词 / 加改写示例（安全）：只影响 reference.md 文字。
- 动 grep 正则（要用户多看一眼）：影响 SKILL.md 机械扫描的拦截行为。

落地前做一次词表一致性自查（见「数据一致性联动规则」），确认该同步的两处都在同一个 diff 里，没有只改一处。

## 第 5 步 确认后落地

把 diff 给用户，等确认。人工触发和自动触发都走这一步，不静默改。

确认后用 Edit 增量改 morrow-style 的对应文件：只加或改指定条目，不重写整个文件、不删除现有条目（除非用户明确要求）。不引入任何 git 操作。

## 数据一致性联动规则

morrow-style 里同一个词存在两处：reference.md 的黑名单全表（带解释、替代词、归因，供人和 Claude 读），和 SKILL.md 自检里的 grep 正则（机器扫描，第一条命中必为 0、第二条逐一人工判断）。两处必须一致。

按类别决定联动：
- 类别 1 绝对禁用 / 3 套话短句 / 5 AI 高频词：加进 reference.md 对应类目，且必须同步加进 SKILL.md 自检「第一条」grep。两处改动放同一个 diff。
- 类别 2 条件禁用 / 7 直译腔技术词：加进 reference.md 对应类目，且同步加进 SKILL.md「第二条」grep。
- 类别 4 空洞书面语：分情况判断。若是固定的、判别性强的短语（如「不可否认」「毋庸置疑」，它们已在第一条 grep 里），有稳定可匹配的固定词形，要同步加进 SKILL.md 自检「第一条」grep；只有随语境才空洞的表达（如「场景落地」在某些口号语境里才算 AI 味），才纯加 reference.md 文字规则，注明「无固定词形，仅文字规则」。
- 类别 6 协作痕迹：通常无单一 grep 词可表达，只加 reference.md 文字规则，diff 里注明「这条无法用 grep 表达，仅文字规则」。
- 结构性硬禁项（比喻、金句、三段式等）：改 SKILL.md 硬禁项清单文字；若该硬禁项包含固定词形（如「彰显」「凸显」「标志着」「见证了」「里程碑」「新篇章」这类宏大意义拔高词，它们已在第一条 grep 里），固定词要同步加进 SKILL.md 自检「第一条」grep；只有无固定词形的结构问题（比喻句式、金句结构、三段式排比等）才仅改硬禁项清单文字，注明原因。

reference.md 第 1 类词表和 SKILL.md「第一条」grep 有重叠，改任一处都要核对另一处，保持词表一致。

## 错误处理与边界

- 冲突和重复：落地时若发现该词其实已在别的类里，不重复加，提示时须明确指出属哪个体系（如「已存在于 reference.md 第 X 类」或「已存在于硬禁项第 X 条」），并问用户是否要调整分类或补充语境说明。
- 词表一致性校验：第 4 步生成 diff 后、落地前，把要加的词对照 SKILL.md 两条 grep 和 reference.md 全表，确认该同步的都同步了。这是本 skill 指令里的一个自查步骤，不是外部脚本。
- 破坏性改动边界：只用 Edit 增量改 morrow-style 的两个文件，不重写整个文件、不删除现有条目（除非用户明确要求）。改的是 ~/.claude/skills/ 下的全局文件，属仓库外，每次改前给 diff 确认，不走 git。
- 空输入 / 全部误判：若输入的词经准入测试全部不通过，如实说「这批没有需要录入的」，不硬凑。
